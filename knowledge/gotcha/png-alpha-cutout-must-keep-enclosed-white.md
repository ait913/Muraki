## Context

白背景で生成した 3D/イラスト系のキャラクター画像を透過 PNG に切り抜いて出荷する。ライトモードでは何年も問題なく見えていたのに、**ダークモードにした瞬間にキャラの白い部分に穴が開いて背景の黒が透ける**。

atender のマスコットで実際に起きた。`mascot-hello-1024.png` は **52,527px (全画素の 5.0%) が穴**で、最大の穴は 30,159px (顔まわりの白がまるごと抜けていた)。web 用の 4 枚も全部同じ (794〜5,589px)。

## What

原因は切り抜きの実装が **「明るい画素 = 背景」** で抜いていたこと。キャラ自身が白を持つと (白い体・白い顔・輪の内側) それも一緒に抜ける。

正しい規則は **「画像の外周に連結した白だけを背景とする」**:

```python
white = (rgb.min(axis=2) > 246).astype(np.uint8)
_, lab = cv2.connectedComponents(white, connectivity=4)
border = set(lab[0, :]) | set(lab[-1, :]) | set(lab[:, 0]) | set(lab[:, -1])
outside = np.isin(lab, list(border)) & (white == 1)
foreground = ~outside        # ★ 囲まれた白は前景として残る
```

### 受入基準は「穴 0」にできない

穴 = **画像外周に連結しない `alpha == 0` の 4-連結成分**。正しく切り抜いても、拡大縮小 (LANCZOS) の undershoot が alpha 端で 0 に張り付くため **1〜30px の微小な穴が必ず数十個残る**。承認済の参考出力にも 16 個 / 27px あった。なので面積で切る:

| | 壊れている資産 | 正しく切り抜いた資産 |
|---|---|---|
| 最大の穴 | 360〜30,159 px | 5〜30 px |
| 穴の総面積 | 全画素の 0.63〜5.0% | 0.003〜0.12% |

→ 基準は **「面積 64px 以上の穴が 0 個」+「総面積が全画素の 0.2% 以下」**。壊れ側と 12〜1000 倍の余裕がつく。

### テストは「穴を打ち込んで落ちること」まで書く

判定コードは「穴が無い画像」に対しては常に緑を返すので、**それだけでは無力かどうか分からない**。読み込んだ画像に半径 20px の透明な円を打ち込み、判定が必ず落ちることを同じテストで示す (負のコントロール)。

**合成円より強い負のコントロールがある**: `git show <merge-base>:<png>` で**壊れていた実物**を作業ツリーに当てて同じテストを走らせる (`cp` バックアップ → 実行 → 復元 → md5 突合)。atender build 16 では 6 ファイルで **A 基準が 18 / 18 / 7 / 3 / 2 / 4 個の large hole を検出**して per-file に赤くなり、「出荷済のバグを実際に捕まえる」が直接示せた。合成円は「判定が動く」ことしか示さない。

**判定コード自体の裏取り**: Swift の自作 BFS (テスト側) と Python cv2 の `connectedComponentsWithStats` (レビュー側の独立実装) が壊れ資産で**総面積を完全一致で返す** (52527 / 4063 / 794 / 1638 / 5589) ことを確認すると、「テストのアルゴリズムが間違っていて緑」を排除できる。

## Why

「白背景を抜く」は閾値の問題ではなく**トポロジの問題**。背景は「外周からつながっている領域」であり、色ではない。閾値だけで抜くと、キャラが背景と同じ色を持つ瞬間に破綻する — そして白背景 + 白いキャラは生成 AI のイラストで最も多い組み合わせ。

ライトモードでは背景 (白) と穴 (透明→白が見える) が同色なので**症状がまったく出ない**。ダークモード対応の日に初めて噴き出し、しかも「画像が汚い」という曖昧な体感で報告される。

## How to apply

- 「ダークモードでキャラ/ロゴに穴・黒い点が出る」→ まず alpha の穴を数える (上の `holes()`)。画像の作り直しや inpaint の前に**切り抜き手順**を疑う
- **inpaint での修復は期待しない**。穴とキャラの「本来黒い部分」(目・口・線画) を区別できず、顔が潰れる (atender で試して失敗)
- 原画シートが残っているなら**再切り出しが最短で、キャラの同一性も保たれる** (再生成すると別のキャラになる)
- 切り出しスクリプトはリポジトリに置く (`tools/*.py`)。窓 (bbox) と影の除去行は「人間が決めた定数」として表に書く — 行幅プロファイルの段差のような自動検出は**ポーズによって効かない** (5 ポーズ中 1 つで最大段差が 5px しかなく検出不能だった)
- framing (canvas に対するキャラの占有率) は**現行出荷物に合わせる**。alpha を直すついでに大きさを変えるとレイアウトが動き、「何を直したのか」が分からなくなる
