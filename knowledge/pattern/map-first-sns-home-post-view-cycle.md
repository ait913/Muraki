## Context

Bloom. (位置情報 SNS) の Phase-0 IA。全画面地図を維持しつつ、主サイクル「通知 → 3 秒動画 → 投稿先を選んで投稿 → その場で他人の投稿も見る」をホームから 3 タップ以内で回す必要があった。地図 / フィードのタブ分割、上部ストーリーズ列、フィード専用画面を比較して 1 案に決めた。

## What

採用: **Zenly 骨格** = 全画面地図の上に投稿をアバター付き丸サムネ (メンバー色リング) で浮かせ、下端に**常設ボトムシート (peek / half / full)** を置き、peek = 状態行 + 当日投稿のストリップ、half 以上 = フィード本体。撮影ボタンは peek の上端に半分かかる中央 FAB。**投稿完了の着地 = シート full (自分の投稿が先頭、以下他人の当日分)** でゲートなしにサイクルを作る。地図は「どこで」、シートは「誰が・何を・いつ」を担い、同じ投稿に 2 つの入口ができる。

必要な時だけ出す機能 (集合ボタン等) は**常設ボタン 1 つ + 発生時のみ peek にカード** (Beer Buddy 型) にし、ホームの主役を奪わせない。

不採用の理由: タブ分割は「どこで」と「何を」が別画面に割れて撮った直後に地図が消える / 上部ストーリーズ列は地図面積を食い、上部はセグメント・グループ名で既に埋まる / フィード専用画面は主サイクルの着地が地図から離れる。

## Why

毎日のタスク (撮る・見る・眺める) が 1 画面上で完結し、通知の着地先が全部ホームで済む (「戻る」が壊れない)。progressive disclosure の 2 段制限も守れる (ホーム → シート/全画面で打ち止め)。

## How to apply

- 「地図 + 何かのリスト」を持つアプリのホームは、まずこの骨格 (地図 + 常設シート + 中央 FAB) を初期案にし、タブ分割は不採用案として理由を書く
- 常設シートは drawer 扱いで modal sheet と両立させる (modal 表示中は peek に畳む、同時 1 枚)
- 主サイクルの「着地画面」を先に決めてから動線を数える。閲覧を投稿にゲートしない場合は着地でサイクルを作る
- ペルソナ表に「投稿への態度」の行を持つ (見る専・撮らされ疲れ・遠出の日だけ、が動線の既定値を決める)
