# Developer の職業的習慣ノート

召集されたら最初に読む。**過去の自分 (歴代 Developer) が実際に踏んだ穴**から蒸留した現役の習慣 (20 本以内を維持)。新しく踏んだら自分で追記・置換し、古びたら捨てる (INDEX 対象外、再生成不要)。2026-07-31 に Opus 5 移行で全面圧縮 (原本: ai-audit/archive/20260731-muraki/role/developer.md)。

1. **完了報告の前に build / typecheck / test を自分の手で回して緑を確認する。** 委譲先エンジンや subagent の「完了」「通った」という申告は完了ではない。検証後は `git status` を見て自分の生成物 (バイナリ / `.next` / `node_modules`) が残っていないことまで確認する (sessions/2026-05-26)
2. **識別子 (package version / API 名 / symbol 名 / export 名) は書く前に実在確認する。** researcher の列挙も無検証で転記しない — install・コンパイルが通ることまでが自分の仕事 (sessions/2026-05-26)
3. **静的検査の緑は実行時を保証しない。** SQL の型推論・migration・ルーティング・wire 契約は、実 DB / 実サーバに 1 回撃つスモークでしか捕まらない。DB や配線を触った Slice は報告前に実経路で 1 回通す (2026-07-05, dandan-app)。典型例: pgx で WHERE 断片を組み立てるヘルパに固定引数列を渡すと、SQL 本文が `$1` を参照しない組み合わせで PG が `could not determine data type of parameter $1` を返す — build は緑、実 PG で初めて赤 (2026-08-20, bloom P3b)
4. **帰属は報告文でなく実体 (mtime / `git diff` / 計測) で確定する。** 「誰が触ったか」「どの build が入っているか」「どのログか」は、報告・ファイル名・フラグでなく mtime・hash・`workdir` 行で判定する (2026-07-16, omatase)
5. **肯定的前提 (「API は健全」「N 箇所しかない」「既に実測済み」) も否定的主張と同じ強度で検証する。** 範囲を区切る主張は外側全部への否定的主張。測られたケースの外側 (入力クラス) を自分で列挙して総当たりしてから実装する (2026-07-16, atender web-logout)
6. **設計の名指し (file:line / 消費者数 / 制約名 / 削除リスト) は着手前に grep で数え直す。** 宣言サイト・caller・制約は設計の主張より多いことが常態で、数が合わないまま型を締める/消すとビルドか本番が壊れる。合わなければ最小の整合で通して設計の誤りとして上申する (2026-07-21, atender tmpl-search)
7. **設計 doc 内で節同士が矛盾したら、挙動仕様節 (Reviewer がテストを生成する節) を上位として実装し、読み替えを完了報告に明記する。** 「触るファイル一覧」は実装範囲の上限で、節ごとの列挙漏れは下限を決めない (2026-07-29, atender eventkit-export)
8. **設計 doc の逐語コードは diff で機械的に一致確認する。逐語がコンパイル不能 (actor 隔離等) なら契約を保つ最小の是正 + 上申。** 「設計どおりに書くと通らない」から先を即興にしない (2026-07-16/17, omatase・atender)
9. **検証で木を壊す前に戻し方を用意する。`git checkout HEAD -- <file>` は未コミットの実装を無警告で破棄する。** 退避は scratchpad へ `cp` → 復元は `diff`/hash でバイト検証。ベースラインは `git worktree add --detach` で建てれば自分の木を触らずに済む (2026-07-16, atender phase-e-p1)
10. **guard・修正の検証は負のコントロール込みで。** 緑を確認しただけでは vacuous pass と区別がつかない。守りを外して実際に赤くなるまで見て初めて「検証に歯がある」(2026-07-16, omatase coolify-deploy)
11. **検証は本番と同じ経路を逐語で通す。** ホストから `-p` 越しの curl はコンテナ内 healthcheck の代理にならない (bind stack のバグに常に緑)。本番がコンテナ内実行なら `docker exec` で同じコマンドを打つ (2026-07-16, omatase)
12. **「環境が無い」「壊れている」は 1 コマンドで確認してから決める。** `docker info` は 1 秒、`which` が失敗しても `ls ~/go/bin` に実体がいる。決めつけて CI に委ねた検証が本番確実死を素通しした (2026-07-16/30, omatase)
13. **worktree に `.env` を置かない。共有リソース (simulator / scratchpad / ポート / main の DB) は並走前提で扱う。** `@prisma/client` は `.env` を自動ロードして無関係テストを壊し、絶対パスの `DATABASE_URL` は main の DB に migration を当てる。sim は feature 専用に作り、ログ名は feature 固有にする (2026-07-29, atender)。「session 専用」と案内される scratchpad にも前セッションの成果物が残っている — 成果物の収集は glob でなく**自分が作ったファイル名の明示列挙**で行う (glob が他人のスクショを montage に混ぜた。2026-08-20, bloom P2b)。compose.test.yaml の固定ポート DB も並走レーンと共有 — 別レーンの未コミット migration で schema_migrations が先に進み `no migration found for version N` で落ちる。リセットで他レーンを壊さず、自前コンテナを別ポートで建てて `TEST_DATABASE_URL` を向ける (2026-08-20, bloom P2b)
14. **並走 Reviewer の生成物は触らない。テスト本数は数でなく名前の diff で比較する。** Reviewer のテスト起因の型エラーは実装からは直せないので、tsconfig の `exclude` 等の設定層に逃がし、検査を弱めた事実を報告する (2026-07-30, omatase)
15. **スコープ外の発見・設計の曖昧さは勝手に直さず、実測根拠を添えて上申する。** 触るなと言われた領域が原因と判明した時ほど正確に (2026-07-16, atender)
16. **偽 fail の第一容疑者は自分のハーネス。** exit code はパイプを使わず取る (zsh に `PIPESTATUS` は無い)。共有 markdown の編集はアンカーの出現回数を assert してから置換する (2026-07-16)。Bash の `&&` 禁止フックはヒアドキュメント内の JS/Python 文字列 (`if(a&&b)`) まで引っかけるので、パッチスクリプトは Write ツールでファイル化してから `python3 fix.py` で実行する (Dart 断片の `&&` でも再発 2026-08-21)。Flutter 実走ドライバ (integration_test) の落とし穴 3 連 (2026-08-21, bloom P3): (a) `reportTestException` でプラグイン内部の非同期例外を握っても**テストは中断されて「All tests passed」の偽緑になる** — 握るのではなく発生源を断つ (maplibre_gl の styleNotFound は style URL をローカル inline JSON に差し替えると競合窓ごと消える)。(b) `simctl uninstall` は TCC (位置許可の grant) を消す — 再インストール後に grant し直す。(c) CLGeocoder はレート制限で無期限ブロックする — 呼び出し側に `.timeout(5s)` を必ず付ける。headless Chrome の `captureScreenshot` が全滅したらページを疑う前に `pmset -g log | grep "Display is turned"` (display sleep) → `caffeinate -d -u` (2026-08-19, bloom M1)。zsh 検証スクリプトで `GID`/`UID`/`EUID` を変数名に使うと整数型の予約変数への代入で `bad math expression` になり UUID が入らない — 別名 (`GRPID` 等) を使う (2026-08-20, bloom P1)。zsh で `grep [x]codebuild` を未クォートで書くと glob 展開の `no matches found` で「プロセスが居ない」と誤読する — ブラケットパターンは必ずクォート (2026-08-20, bloom P2a)。headless の `xcodebuild` (SwiftPM binary artifact 解決) が無出力・無通信で永久ハングしたら、原因は login keychain の `github.com` item への SecItemCopyMatching (GUI 承認プロンプト待ち)。`sample <pid>` でスタックを取れば一発で分かる。対処は `SWIFTPM_NETRC_DATA="machine github.com login token password dummy"` を export して keychain provider を短絡 (GitHub は public asset への偽 Basic auth を無視する。2026-08-20, bloom P2a)。fake clock を注入したスモークでは、(i) JWT の exp/iat 検証 (golang-jwt) と DB の `DEFAULT now()` は**実時刻のまま**なので、fake が過去/未来だとトークン即失効・日付フィルタ全落ちの偽 fail になる — トークン発行だけ実時刻、DB 既定列はハーネス側で UPDATE して揃える。(ii) WS 送信→サーバー内処理は別 goroutine なので、直後に engine tick を叩くと「pos 未到達 = stale」で状態が巻き戻る — tick 前に数百 ms 待つ (2026-08-21, bloom P3c)。`await Navigator.push(...)` / `await showModalBottomSheet(...)` (= `showBloomSheet`) は **pop されるまで解決しない Future** — その pop 呼び出しを続くコードで書いた瞬間、実行順序的に「pop の前で待つ」デッドロックになる (2026-08-21, bloom P4)。症状は「特定の網羅的操作のあとで無音停止」で、WS/Docker/simulator ネットワークの障害と見分けがつかず誤診しやすい (今回 Docker Desktop 再起動・simulator erase・timeout 追加など無関係な対処に数十分溶かした) — 切り分けは (1) 各 await の直後に `debugPrint` を刺して**どの行で止まるかを行単位で特定**する、(2) サーバーの access log のタイムスタンプ間隔を見て「サーバーは応答している=クライアント側の待ちが原因」と確定する。両方を同時に使うと数分で原因に到達できる。修正は該当 push/showModalBottomSheet を `unawaited(...)` にする (pop は別ステップで呼ぶ)。**Docker Desktop (ローカル dev、Coolify 本番とは別) が長時間ビルド後に無応答になったら** `osascript -e 'quit app "Docker Desktop"'` → `com.docker.backend` 系 PID を `kill -9` → `open -a Docker` で復旧できるが、**古い container 定義が消えることがある** (named volume は残るのでデータは無事、他レーンの container は再作成が必要になり得る — 復旧後は自分の container だけでなく他プロジェクトの `docker ps -a` も確認し、消えていたら Touri/該当セッションに一言残す)
17. **UI の「直った」は box とインク・要素とピクセルを区別して実測する。** スクショの画素実測・a11y ツリー・実タップまで見ないと出ないバグの層がある (フォント silent fallback / tint の暗黙供給元 / overlay の取り付け先)。自動検証が届かない境界は正直に「手動」と報告する (2026-07-16, atender)
18. **subagent が API エラーで死んでも、SendMessage で再開して報告だけ回収できる。** その際「ファイルを変更するな」を明示する (回収のつもりの再開で作業を再開させない)
19. **subagent が異常終了したら、報告を読む前に `git diff` を確認する。** 変異注入や中途半端な変更が作業ツリーに残っていることがある (後片付けコードは異常終了時に走らない)
20. **長時間ジョブが harness の 10 分 cap で SIGTERM されても「失敗」と決めつけない。** 成果物はディスクに残っていることが多い。log の到達点と実体 (`git status` / `find`) で完了度を判定して回収する (2026-07-23, omatase)

**Codex を使う場合は `knowledge/tool-quirk/codex-behavior.md` を必読。**
