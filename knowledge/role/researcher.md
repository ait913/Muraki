# Researcher の職業的習慣ノート

召集されたら最初に読む。**過去の自分 (歴代 Researcher) が実際に踏んだ穴**であり、予防的な網羅ルールではない。新しく踏んだら自分で追記・置換する (INDEX 対象外、再生成不要)。

- **package version は必ず `npm view <pkg> version` で 1 個ずつ実機確認する。同系列パッケージだからと version を推測列挙しない。** 推測した `@tanstack/router-plugin@1.170.8` が npm に存在せず install 全 abort の実績 (sessions/2026-05-26)
- **「○○を参考に」と言われた対象は、要約・既存 knowledge より先に一次ソース (実コード・実機・配信 CSS) を読む。** 要約と一次ソースが食い違ったら一次ソースが正。既存 knowledge の「record に type を保存」誤記を実コードで訂正した実績 (sessions/2026-06-08)、一次ソース研究を飛ばして CF ダッシュボードを輸入し「センスがない」と却下された実績 (同)
- **切り分け依頼は推測で答えず、コード + 実プローブ (API 直叩き等) で断定する。** 「事実ベースで」の切り分けがデッドロックの単一真実を突き止めた成功例 (sessions/2026-06-11 #36)
- **`gemini -p` が `IneligibleTierError: This client is no longer supported... migrate to Antigravity` で落ちる時がある (2026-07)。CLI の free-tier 廃止。** その場合は WebSearch + WebFetch (公式 docs 直読み) + codex で代替。gemini 復旧を待たず即フォールバックせよ。加えて `codex` が PATH に無い環境もある (`command not found: codex`) — 事前に `which codex` で確認し、無ければ WebFetch/WebSearch で公式一次ソースを取りに行く
- **Apple HIG ページは WebFetch だと JS レンダリングで本文が取れず、モデルが一般知識で穴埋め回答してくる (出典として無効)。`https://developer.apple.com/tutorials/data/design/human-interface-guidelines/<slug>.json` を fetch すれば実本文が取れる。** tab-bars で「アクセスできないが一般知識で答える」ハルシネーション回答を掴みかけた実績 (2026-07-05)。「I don't have access」系の前置きがある WebFetch 出力は出典として採用しない
- **developer.apple.com (HIG含む) は SPA で WebFetch では本文が取れない。`/tutorials/data/design/human-interface-guidelines/<slug>.json` を curl で直叩きする。** WebFetch 4連続空振りの実績 (2026-07-05)。詳細: knowledge/library/apple-developer-docs-json-endpoint.md
- **「あるフィールドが空/None だから X ではない」と推論する前に、必ず対照群を1つ引く。** `fonts.google.com/metadata/fonts` の `license` が `Google Sans → None` だったので「OFL ではない=proprietary」と断定しかけたが、Inter/Roboto/Open Sans も全部 `None` だった (= API がそもそも license を出していない) (2026-07-16)。単一サンプルの欠損は「対象の性質」ではなく「データソースの性質」であることが多い。代わりに `api.github.com/repos/google/fonts/contents/{ofl,apache,ufl}/<name>` の 404 で裏を取った
- **規約系ページ (developers.google.com 等) は WebFetch より `curl -sL` + HTML strip の方が確実に全文が取れる。** developers.google.com/identity/branding-guidelines は curl で本文・色コード・Do/Don't まで完全取得できた (2026-07-16)。仕様の数値 (padding 等) が図版 PNG に埋まっている場合は画像を落として Read tool で読む — これで Google の button spec 実数値を取れた
- **`codex exec "..."` のプロンプトに backtick を入れるな。Bash の二重引用符内でコマンド置換として展開され、`(eval):1: command not found: output:` 等になってプロンプトが壊れる。** さらに信頼済みディレクトリ外では `--skip-git-repo-check` が無いと `Not inside a trusted directory` で即死する。プロンプトは heredoc (`<<'PROMPT'`) でファイルに書き `codex exec --skip-git-repo-check "$(cat f.txt)"` で渡す (2026-07-16)。なお codex は 10 分無出力のまま返らないことがあるので、**待ち時間の間に自分で一次ソースを取りに行く**方が速い。★ さらに `codex exec` は **stdin を閉じないと `Reading additional input from stdin...` で無限に固まる**。background 実行では必ず `codex exec ... < /dev/null` にする (2026-07-17 に丸ごと 1 回空振り)
- **「ビルド成果物のレイアウトはどうなるか」系は issue tracker を読むより実際にビルドしろ。** omatase の Next.js 16 standalone 調査で、リポジトリを scratchpad に clone → `output: "standalone"` を足して `next build` → `find` で実レイアウトを確認、が 5 分で確定した (2026-07-16)。open issue (#84257) は「バグ報告」の体裁なので現行挙動かどうかが読み取れず、実測が唯一の決着。ローカルに toolchain がある PJ では常にこれを第一手にする
- **「API に無い」系の既存 knowledge は openapi.yaml 由来かを疑い、controller の `$allowedFields` / validator / model の `$fillable` を読み直す。** coolify-api.md の「`health_check_type` は API から設定できない」は openapi.yaml しか見ていなかったための誤記で、実装は POST/PATCH 双方で受け付けていた (2026-07-16 訂正)。**spec 乖離が常態のプロダクトでは、spec の欠落を「機能の不在」と読まない**
- **ソースを読んで断定する前に、その版が「稼働中の実物」と一致するか確かめる。** Coolify を `main` HEAD で clone して読んだ後、`GET /api/v1/version` で本番が **4.1.2** = clone の `config/constants.php` と同版だと確認できたので、実装読みをそのまま設計材料にできた (2026-07-16)。一致しなければ実装読みは「将来の話」であって現状の根拠にならない。**版の一致確認は 1 コマンドで済む。必ずやる**
- **「healthcheck が通る/通らない」は生成コマンドを逐語でコンテナ内実行して確かめる。ホスト側 curl は代理にならない。** `nginx:alpine` は IPv4-only bind (omatase で Node を殺したのと同条件) なのに healthcheck が通る — **実 curl を同梱しているから**で、busybox wget 単体は同じ `localhost` で `Connection refused` になる (2026-07-16 実測)。「alpine だから wget で通る」のような**イメージ族での一般化は誤る**。1 イメージずつ `command -v` と逐語実行で見る
- **Apple docs の JSON エンドポイントは HIG (`/design/human-interface-guidelines/<slug>.json`) だけでなく API リファレンスにも効く: `https://developer.apple.com/tutorials/data/documentation/<path>.json`。** `metadata.platforms[]` に `introducedAt` / `deprecatedAt` が入っており、**availability の一次ソースはこれ 1 本で足りる** (2026-07-17)。`swiftui/view/scrolltargetbehavior(_:)` のような記号名もそのまま小文字 path で引ける。codex に「このAPIは何 iOS から？」を投げると SDK の `.swiftinterface` を grep しに行って 10 分以上かかるので、**docs JSON を自分で curl する方が桁で速い**。codex は突合用のセカンドオピニオンに回す
- **App Store のページを WebFetch すると、Apple サイト自身のナビ (`Today` / `ゲーム` / `アプリ` / `Arcade`) を「そのアプリのタブ構成」として混ぜて返してくる。** TimeTree のタブ構成を聞いて App Store のグロナビが返ってきた実績 (2026-07-17)。アプリ内 IA の出典に App Store ページを使うな。バージョン番号・更新日・説明文・リリースノートは取れるので、そこだけ使う
- **調査対象サイトが SPA / Cloudflare 越しだと curl でも `Loading...` / `Just a moment...` しか返らない (penmark.jp, support.timetreeapp.com で実測 2026-07-17)。** この場合は諦めて「未確認」と書くか、公式ニュースルーム・プレスリリース・App Store 説明文など**静的に配信されている別経路**に回る。★ 併せて、**既存 knowledge の source URL がこの手の SPA だと後から誰も再検証できない**。既存 knowledge の主張を引用する時は「出典が再検証可能か」を見て、不能なら『未再検証』と添えてリーダーに渡す
- **Apple/Swift の API 実在確認は docs より先に SDK の `.swiftinterface` を grep しろ。シグネチャと `@available` が逐語で載っている唯一の一次ソースで、docs より速い。** `$(xcrun --sdk iphonesimulator --show-sdk-path)/System/Library/Frameworks/<FW>.framework/Modules/<FW>.swiftmodule/arm64-apple-ios-simulator.swiftinterface`。**framework の分割に注意** — Liquid Glass の `Glass`/`glassEffect` は SwiftUI でなく **SwiftUICore** にあり、SwiftUI 側だけ grep して「無い」と誤判定しかけた (2026-07-17)。型名に `SwiftUICore.` プレフィクスが見えたらそこが実体。確認は `swiftc -typecheck -target arm64-apple-iosXX.Y-simulator` で実証まで持っていく (30秒)
- **「deployment target を上げたら何が壊れるか」はファイルを書き換えずに `xcodebuild ... IPHONEOS_DEPLOYMENT_TARGET=26.0` で実測できる。** 推測やドキュメントで語る前に 1 回ビルドしろ。atender は無改変で BUILD SUCCEEDED = 移行コストゼロが 3 分で確定した (2026-07-17)
- **developer.apple.com/support/app-store/ の OS 採用率は JS レンダリングで WebFetch では取れないが、HTML 内の `data-bar-chart='[...]'` 属性に生の数値が入っている。** curl + 属性抽出で Apple 公式の実測値が取れる (2026-07-17)。サードパーティ (Mixpanel 等) に落ちる前にここを見る
- **正規表現で HTML を舐めるとき `.{60}(...).{60}` 系の貪欲パターンは catastrophic backtracking で 120s タイムアウトする。** grep -oE で実際に固まった (2026-07-17)。HTML 抽出は最初から python で書く
