# Reviewer の職業的習慣ノート

召集されたら最初に読む。**過去の自分 (歴代 Reviewer) が実際に踏んだ穴**から蒸留した現役の習慣 (20 本以内を維持)。新しく踏んだら自分で追記・置換し、古びたら捨てる (INDEX 対象外、再生成不要)。2026-07-31 に Opus 5 移行で全面圧縮 (原本: ai-audit/archive/20260731-muraki/role/reviewer.md)。

1. **negative control (負のコントロール) は「バグ修正系のリリースゲートでは標準」。** 修正前コード (`git show <merge-base>:<file>`、未コミットなら召集時の `cp`/`tar` バックアップ) に戻してテストが落ちることを確認してから GREEN を出す。「テストが実装に迎合していないか」はこれだけが証明できる (sessions/2026-06-11)。全レビューでの一律義務ではない — 軽量パスでは要求しない
2. **変異は「届いたこと・向き・入口」を証明する。** site 数を `grep -c` で数えて置換数と突合し (2 site 目が生き残る)、ガードを弱める向きに当て (`or true` で包むとパラメータ数を保てる)、公開 API から最初に通る site に当てる (helper 側は早期 return に隠れる) (2026-07-17/30)
3. **負のコントロールで生き残ったテストは 1 本ずつ説明する。** 「殺せなかった本数」を説明できて初めて完了。TZ シフト等の変異はシフト窓に標本が無いと原理的に検出できないので、境界窓の標本は自分で足す (2026-07-17, atender)。「赤くならなかった」はテストの無力の証明という成果 — そこで止めず実経路を踏む別レイヤのテストを新設して赤→緑まで示す
4. **偽 fail の第一容疑者は自分のハーネス。** 全シナリオが同じ異常値なら fixture・起動待ち・ルーティング・mock の shape (W3C エラー型の定数プロパティ / RTL の cleanup 忘れ / エポック手計算) を先に疑う。mock の shape は既存 fixture ヘルパから採り、手打ちしない (2026-07-16)。WS ライブラリ (`coder/websocket` 等) は「呼び手の ctx timeout でも接続を閉じる」契約のものがある — 短命 ctx で `Read` をポーリングすると自分の Read が接続を壊し「サーバーが早期切断した」ように見える偽観測になる。1 コネクション 1 回の長い block Read で検証する ([[gotcha/coder-websocket-short-lived-read-context-closes-connection]]、2026-08-21 bloom P3c)
5. **偽 RED / テスト全滅は本番経路の直接プローブで切り分け、帰属は観測レベルで書く。** ブラックボックスでは「未配線」と「配線済みだがエラー握り潰し」を区別できない — 断定せず観測を書く (sessions/2026-06-11)
6. **ベースラインは台帳と照合し、台帳に無い失敗は「未分類」と明記する。** 台帳は「測った日 + コミット + failure 数」まで要求し、実測と食い違ったら実測を正として台帳をその場で置換する (sessions/2026-06-11, 2026-07-16)
7. **召集されたら最初に「テストが 0 本ではないか」を見る。** 削除されたテスト + `[no test files]` + exit 0 = 中身ゼロの緑。`passWithNoTests` や include の glob ずれも同じ vacuous green を作る (2026-07-30, omatase)
8. **実装を読まずにシグネチャだけ採る手段を持つ:** `go doc` / swiftmodule strings + `swift-demangle` / `tsc --declaration --emitDeclarationOnly` / **Dart は `dart doc --output <scratch>` → 生成 HTML から機械抽出** (クラス・enum 値・定数実値・provider 宣言まで採れる。bloom P2b で全面使用) / 空 `{}` から始める自己発見 decode プローブ / 稼働中 API へのブラックボックス probe。blind を保ったままコンパイルが通るテストが書ける (2026-07-17〜30, 2026-08-20)
9. **設計が規定しない意味論 (store の戻り値・永続化されるフィールド・寛容/厳格の別) を仮定しない。** fixture は SQL 直挿入・実ログインフロー・実 API 採取で作る。「body で受け取らない」は 400 拒否でも 200 無視でも満たされる — status を決め打つと偽 RED (2026-07-05〜23)
10. **設計 doc 内の矛盾 (例示 vs 規範 / 表の値 vs 生成規則) は規範・挙動仕様節を正としてテストし、食い違い自体を報告する。** 「回帰なし」「現行と同一」条項の期待値は設計の文面でなく merge-base の実測から採る (2026-07-29/30, atender)
11. **wire 契約は「同じ値」でなく「形」まで assert する。** serialization の形 (`Z` サフィックス)、error 封筒の `code`/`message` 実値、「キー存在 + 非 null + len」の 3 点セット。status だけの assert は封筒違い・null 化を素通しする (2026-07-05〜30)
12. **ポリシー定数をテストにリテラルで焼かない。** 定数を import して `MIN±1` から導出する。焼くと定数を上げたリリースで必ず陳腐化する (2026-07-29, atender)
13. **手元 TZ に寄生した緑を疑う。`TZ=UTC` で 1 回掃引する。** 端末ローカル暦が仕様である側は「TZ 非依存の標本」と「TZ gate 付き逐語標本」の 2 系統に割る (2026-07-17/30)
14. **in-process テストの原理的な穴は判定に明示する。** Vitest は CJS/ESM interop バグを検出できない (子プロセス probe が唯一の担保)。hook に癒着したロジック・View の `.task` 配線は純関数の緑では 1 ミリも証明されない。「カバーできていない挙動」を GREEN の中に書く (2026-07-16/17)
15. **検証で環境を壊さない。** 書き換えたら `cp` バックアップ → バイト単位復元。`git checkout --` は Developer の未コミット実装を HEAD に戻して消す。変異注入は使い捨て detached worktree で回す (途中で異常終了しても本番の木が無傷)。dev の `.env` の値は dev として正しいので「直して」放置しない (2026-07-17/30)
16. **「テストがあるか」でなく「テストがその配線を実行するか」を見る。** DTO 層と client 層が個別に緑でも、両者を繋ぐ `as:`/型引数/実経路は無テストのことがある (2026-07-17, atender)
17. **UI 検証は assert を書く前に実体を採る。** `app.debugDescription` を 1 回吐く / pixel assert は対象色が実際にビットマップに出るか probe してから書く。判定はフラグ・スクショの名前 (`_ok=true`) でなく中身 (byte hash / pixel 計数 / 2 候補値のどちらに近いか) で行う。flaky 疑いは同一コードで 2 回回して顔ぶれを比較してから regression を語る (2026-07-17〜30)
18. **GREEN を束ねない。** 「修正が効いたと証明できた件」と「非退行しか言えない件」を割って報告する。手動確認送りにした境界も明示する (2026-07-30, atender)
19. **subagent が API エラーで死んでも SendMessage で再開して報告だけ回収できる (「ファイルを変更するな」を明示)。異常終了したら報告を読む前に `git diff` を確認する** — 変異や中途変更が木に残っていることがある (gotcha/mutation-testing-agent-crash-leaves-mutation-in-tree.md)
20. **実装が設計に忠実でも、失敗の帰属先が設計の不備なら設計の不備として報告する。** 「実装 or 設計」の切り分けまでが判定 (2026-07-16, omatase)
21. **成功応答だけの dio/fetch capture テストで満足しない — エラーコード分岐のある設計 (409/403/410 等) では最低 1 本、意図的に非 2xx を注入する負のコントロールを書く。** Dio は `validateStatus` 既定 (2xx のみ成功) のまま非 2xx を返すと、独自エラー封筒→例外変換ロジックより先に生の `DioException` を投げる。P2b の成功系テストでは気づけず、P3 で初めて発覚 ([[gotcha/dio-default-validatestatus-swallows-custom-error-envelope]], 2026-08-21 bloom)。**dart doc で Implementation セクションが出るのはトップレベル `final` 変数 (Riverpod provider の初期化式など) だけ** — インスタンスメソッドの本体は出ない。前者を読むと実装ロジック (route 定義等) が意図せず見えるので、シグネチャ取得用途では Constructors/Properties/Methods の一覧に留め、Implementation ブロックの多用は避ける
22. **Next.js の `next build` は `tsconfig.include` の `**/*.ts` 経由で `tests/` も型検査する。** テストに型エラーがあるとサーバー起動 (`pnpm build`) が落ち、全 API テストが「No test files / Unhandled Error」で見える。helper の戻り値は `ApiResult<any>` で型付けする (2026-10-02 wasawasa)。better-auth の authorize は `Accept` 無しの fetch だと 302 でなく 200 JSON `{url}` を返す — Location 無しは「未実装」でなく helper 側を疑う
23. **Playwright E2E の偽 fail 4 種 (2026-10-02 wasawasa)。** (a) Radix の `data-testid` は dialog 要素自身に付く → 子孫探索 `dialog.getByTestId` でなく `page.getByTestId`。(b) 行テキストに「失効」「今入れる」等のボタン文言が混ざり、`poll(...).toContain` が再描画前に通る → ボタンの count / data 属性の変化を待つ。(c) モーダル開直後の背景クリックは無視される (人間速度では起きない) → 500ms 待つ。(d) モーダルの中身は非同期ロード (「読み込み中…」、select disabled) → 有効化を待ってから操作。Bash フックは heredoc 内の and-and 記号も弾く → テストは Write で書く。vitest の console.log は握り潰されるので probe は fs.appendFileSync に出す
24. **「別サーバー」系 (env を変えて再起動する項目) は別 DB + 子 env の掃除で立てる (2026-10-02 wasawasa Phase 2 A)。** (a) 本流サーバーと DB を共有すると両方の poller が同じ run を取り合い DS5/DR1 が成立しない → 別ポート + 別 DB (`CREATE DATABASE` + 空 DB 起動で MG1 も兼ねる)。(b) 子の env は `{...process.env, ...over}` でなく親の `COOLIFY_*` 等を落としてから重ねる (undefined を渡しても親の export が勝ち「未設定」の検証が偽 RED)。(c) `BETTER_AUTH_SECRET` 変更は `jwks` 表を空にしてから (しないと全リクエスト 500、RUNBOOK 記載)。(d) 状態を取り込む途中状態 (`sending` など) を「attempts ≥ 1」だけで pending と見なさない。(e) 設計の手順同士が矛盾して再現できない分岐 (DP14: busy 判定の直後にだけ既存デプロイが現れる) は、外部呼び出しの直前に副作用を差し込む転送プロキシで再現する。(f) 全 pass は「盲点が無い」ではない: サーバーログ (tmpdir の `wasawasa-test-server-*/server.log`) を事後に grep して秘密文字列が 0 件であることまで見る
25. **途中状態・喪失系 (復旧・lease・結果不明) は「凍結ヘルパー」で決定的に作る (2026-10-02 wasawasa ゲート修正)。** (a) poller と競合する行を直接書き換える時は、先に他人の lease で塞ぐ → スタブと行を整える → 最後に lease を空にする (塞がずに書くと poller が途中状態を食う)。(b) 一過性の状態 (dispatch_unknown など数百 ms) は、観測を邪魔しない側の依存 (一覧 500 等) を要求の到着後に差し込んで保持してから assert する。(c) 「古い所有者が復帰しても書かない」は SIGSTOP/SIGCONT (所有 pid は lease_owner から取る) で作れる。try/finally で必ず SIGCONT。(d) 列の UPDATE を文字列連結で組むなら列→式の map にしてから結合する (同じ列の二重代入で全滅した)。(e) 「別 DB の残骸 run」が通知件数を汚すので、通知系の assert は rule_name で絞る
26. **「exit code 0 = 全 pass」を信用しない。まず失敗を仕込んだ probe で exit code を確かめる (2026-10-02 wasawasa)。** embedded-postgres は async-exit-hook を import 時に登録し、`beforeExit` で `process.exit(0)` するため vitest の exitCode=1 が握り潰される (globalSetup が PG を起動する構成で再現)。判定は常にログの FAIL 行。E2E で画面が mode ごとに計画 API を叩く (auto / full / server_only / switch_only の 4 本) 設計では `plans.at(-1)` が選択 mode の計画とは限らない → URL の `mode=` で引く。本番扱い (production tier) の環境への POST は `confirm` が要り、確認の 409 が `confirm_stale` より先に出る
32. **「別サーバーに env を足して立てる」前に、その env が実際に効く経路かを確認する (2026-10-04 wasawasa D)。** standalone の `server.js` は `NODE_ENV=production` を無条件に代入し、バンドルでも定数化される。「本番では拒否」ガード付きのテスト用 env は、ビルド済みサーバーでは永久に拒否される (起動ログの migration failed で気づく)。`next dev` で立てれば効くが CLAUDE.md を書き換えるので `git checkout` で戻す。サービス関数を直接呼ぶ unit/API は、設計のシグネチャでなく `tsc --declaration --emitDeclarationOnly` で採った公開シグネチャで呼ぶ — 引数の位置がずれると「確認なしで通る」偽の RED/GREEN を作る。EC のように任意キーが設計に書かれた wire は、部分指定 (1 キーだけ) を必ず 1 本入れる (全キー指定だけだと必須化バグを素通しする)
33. **Flutter で「どの host に送ったか」は HttpOverrides で採る (2026-10-04 bloom env-picker)。** 公開 getter が無い Dio/WS の接続先は、`HttpOverrides.global` に `openUrl` を記録して SocketException を返す HttpClient を差せば黒箱で観測できる (zone 版 `runZoned` は継続が別 zone だと外れるので global + finally で戻す)。ただし WS は「到達条件 (gathering 等)」を作れないと開かれず空振りする → 空振りを緑にせず「未検証」と報告する。AppRoot 越しの実切替は path_provider / flutter_secure_storage の MethodChannel を mock し、`runAsync` で I/O と `pump` を交互に回せば実 boot まで通る。testWidgets 内の素の `await` ファイル I/O はハングするので `tester.runAsync`。macOS の `sed -i` は引数に空文字が要る
34. **drift (NativeDatabase.memory) + Dio の fake adapter は `fakeAsync` の下では完走しない。testWidgets 内でも runAsync が DB のキューに詰まって無限ハングする (2026-10-05 bloom track-blob)。** (a) `Timer.periodic` の周期・stop・二重 start は `runZoned(zoneSpecification: ZoneSpecification(createPeriodicTimer: …))` で Timer を捕まえて手動 fire し、効果は実時間で待つ。(b) testWidgets は「操作 → `runAsync(delay 40ms)` + `pump(50ms)` を交互」で進め、**状態変化 (signOut 等) の直後に `runAsync(db 問い合わせ)` を直で呼ばず、先に pump/runAsync を十数回回して fake zone 側の保留を流す** (直呼びは db キューと fake zone の相互待ちで sync 風に固まり `--timeout` も効かない → `perl -e 'alarm 90; exec @ARGV'` で囲む)。(c) 設計の「何秒後に再開」系は、ForegroundSync 内部ゲートが `DateTime.now()` 固定なので Retry-After を 1 秒にして実時間で跨ぐ。(d) 設計の項目が「どの層の責務か曖昧」(settle が wipe まで含むか) は、層をまたぐ UI テストで観測し、関数単体では冪等な呼びで両対応にする

**Codex を使う場合は `knowledge/tool-quirk/codex-behavior.md` を必読。**
35. **wasawasa の API テストは先に既存テスト 1 本で wire の形を採る (2026-10-05 pages)。** (a) 検証エラーの `fields` は `error.details.fields.<name>` (設計の「fields.x」は省略表記)。(b) 設計が FK `ON DELETE SET NULL` を持つ表 (events.page_id) は、削除系の操作の**後**に page_id を assert すると全 Event が NULL で偽 RED — 先に検査してから purge。(c) リリース削除は `{confirm:<名前>}` 必須、本文なし POST は 415。(d) 設計の例示リテラル (PG1 の本文) は実装と一致しても §4 の規範 (末尾改行なし) と食い違うことがある → 食い違いは報告に残す。(e) E2E の callout は `data-type` でなく `type` 属性、折りたたまれたツリーの子は innerText に出ない
36. **メニュー / ダイアログ起点のフォーカスは「開いた直後」を別テストで見る (2026-10-05 wasawasa pages-ui)。** Radix の DropdownMenu / ContextMenu は閉じる時にフォーカスをトリガへ返すので、直後に `focus()` するインライン入力 (改名) と、Dialog 内の autoFocus (PagePicker の検索欄) が上書きされる実装が出やすい。確定・取り消しの経路テストとフォーカス検査を同じテストに入れると前者まで巻き込まれて止まる → フォーカスは専用テスト (UI6a / UI7a)、本流は 800ms 待ってから `fill`。判定は `page.on("pageerror")` を 1 回仕掛けるだけで原因が出る (`Cannot read properties of undefined` = API 応答の形の読み違い)。Playwright の `<a download>` は `request` / `response` イベントに出ない → `waitForEvent("download")`。モバイルのドロワーは Esc でメニューと一緒に閉じるので、メニューは項目を選んで閉じる。同じ防御が 2 重にある実装 (`disabled` + `useRef` ロック) の負のコントロールは両方外す
37. **エディタ E2E のキー操作は macOS Chrome 前提で書く (2026-10-05 wasawasa code-block)。** Home / End はキャレットを動かさない (Tab を押すと行末に空白が入る偽 RED)。行頭は `ControlOrMeta+ArrowLeft` を `anchorOffset === 0` まで繰り返す (全体実行の負荷でキーが落ちる)。コードの全選択に Mod+A を使うと文書全体が選ばれブロックごと置換される → Shift+↑ + Mod+Shift+←。Mermaid の preview 表示は `pre` が `display:none` で rect が 0 → 位置関係は split / code で測る。末尾がコードブロックの本文をエディタで保存すると `body_md` が `\n\n` で終わる (TrailingNode) ので、設計の期待値に末尾改行が無くても吸収して比べ、食い違いは報告。ビルド済みサーバーを使う変異 (`loose` / IO 判定) は変異ごとに `pnpm build`、戻したら必ず `git checkout -- lib components` + 再 build
38. **Flutter の live 起動 fixture (routerProvider) は同意シートが先に開く (2026-10-06 bloom ui-fixes-2)。** 非 demo の live セッションは `showConsentSheetIfNeeded` で modal が被り、タブ/ヘッダーの tap が「would not hit test」警告のまま空振る (location も segment も変わらず偽 RED)。`tester.runAsync(() => db.kvSet(Consts.termsAcceptedKey, '1'))` を先に。drift watch を持つ画面はテスト本体の最後に `pumpWidget(SizedBox)` + pump 数回で畳む (addTearDown では間に合わず `!timersPending`)。Cupertino シートのスクロール検証は `tester.drag(find.text(...))` でなく中ほどの座標から `dragFrom` (上端付近のテキスト起点だと中身が動かない)。`SheetRow.label` は `find.text` に掛からないので `byWidgetPredicate(w is SheetRow ...)`。video_player は `initialize()` が volume 1.0 を 1 回流すので「常に 0」は「play 前に 0・以後非 0 に戻さない」で書く
