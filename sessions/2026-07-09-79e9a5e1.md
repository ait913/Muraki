## 課題点

- **AI がローカル長寿命プロセスを保持できない**
  - **何が課題か**: bg bash で起動した API がターン終了で kill され、実データ検証が続かない
  - **いつ起こるか**: iOS 実機/シミュレータの実データ動作確認、E2E 系
  - **次どうするか**: 「API起動→seed→build→UITest→xcresult抽出」を**1ターン内で完結**させる(今回のパイプライン)。腰を据えて触るなら Touri のターミナルで API 常駐
- **スクショハーネスの tap がフロー途中で失敗しモーダル未捕捉**
  - **何が課題か**: 連続フロー型テストは前ステップの状態が干渉し `ok=false` でモーダルが撮れない
  - **いつ起こるか**: 特定モーダル/展開状態を狙って撮りたいとき
  - **次どうするか**: 画面ごとに**独立した専用テスト**(launch 直後に対象を tap)にすると確実。accessibilityIdentifier を対象要素に付ける
- **Leader が実装コードを直接編集(役割逸脱)**
  - **何が課題か**: Muraki 規約では実装は developer だが、視覚反復のデザイン微調整を全部 developer 経由にすると「スクショを見て pixel 調整」の往復が高レイテンシで不向き
  - **いつ起こるか**: ユーザーがデザイン修正ループを Leader に明示委任したとき
  - **次どうするか**: 視覚反復系は Leader 直編集を許容する運用でよいか要整理(今回はユーザー明示委任 + レイアウト/余白のみで logic 不触のため直編集を選択)
