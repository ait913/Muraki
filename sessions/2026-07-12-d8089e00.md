## 課題点

- **worktree checkout がタイムアウトする遅い FS**
  - **何が課題か**: iCloud/同期下と思われる FS で `git worktree add` の 100ファイル checkout が 2分の Bash timeout を超え、git がロールバック (ブランチだけ残る) した。venv の `import mcp` も約107秒かかる。
  - **いつ起こるか**: worktree 作成時、venv python 実行時 (このプロジェクトで毎回)。
  - **次どうするか**: worktree 作成・重い python 実行は最初から `run_in_background: true` で投げ、Monitor で完了待ちする。中断時はブランチ残骸を `git worktree add <path> <既存branch>` (‑b 無し) で貼り直す。

- **マージ≠デプロイ (push 忘れで旧コミットをデプロイ)**
  - **何が課題か**: Muraki の Leader マージはローカル main への ff。だが各 PJ は独立 GitHub repo で、Coolify は origin/main からビルドする。push を挟まず redeploy して旧コミットが本番に乗った。
  - **いつ起こるか**: 独立 repo の PJ (agent-hub 等) をマージ後にデプロイする毎回。
  - **次どうするか**: デプロイ前に必ず `git push origin main`。redeploy 後は `GET /deployments/<uuid>` の `.commit` を push したコミットと照合する。agent-hub CLAUDE.md に明記済。
