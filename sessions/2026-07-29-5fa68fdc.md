## 課題点

1. **設計docの「例」と「規範」が食い違う**
   - 何が課題か: D2 §9 A22 の例では `DELETE ?scope=all` に `originalDate` 無し、§4.4 の規範は「必須、欠落は400」。D3 §4.3 と §8 KEY5 でも `kind(of:)` の引数型が非Optional/Optional で割れた。
   - いつ起こるか: 挙動仕様を後から書き足すとき、型宣言節との整合が取られない。
   - 次どうするか: architect に「型宣言節と挙動仕様節を書いたら、両者を突き合わせる」工程を明示させる。reviewer 側は「割れたら規範を採る」で既に対処できている (role note 追記済)。

2. **ハードコード日付とハードコード設定値がテストを自動的に腐らせる**
   - 何が課題か: `personal-calendar-share.test.ts` 6件は reviewer GREEN の**3日後**に日付が過去に滑って自動的に落ちた。`version.test.ts` 4件は `MIN_IOS_BUILD` を上げた瞬間に落ちた。どちらもCIもレビューも検出できない。
   - いつ起こるか: `today()` アンカーの窓を持つ機能、および設定定数を検証するテスト。
   - 次どうするか: gotcha 2本を追加済 (`hardcoded-future-dates-decay-into-baseline-failures.md` / `policy-constant-literal-in-test-decays-on-bump.md`)。設計docのテスト仕様に日付リテラルを書かせない。

3. **ベースライン失敗の山に本物のバグが隠れていた (再発)**
   - 何が課題か: Web 27件が台帳に無いまま約2ヶ月放置され、その中に「コピーを押しても何も起きない」本番バグが埋もれていた。
   - いつ起こるか: 台帳にパッケージ単位の節が無いとき。今回は API と iOS の節しか無かった。
   - 次どうするか: Web 節を新設済。新しいテストスイートを足したら台帳に節を作る。

4. **正典ドキュメントが出荷済みコードと矛盾していた**
   - 何が課題か: `DESIGN.md` が build 11 でタイル化を出荷した後も full-bleed のままだった。D2 §14 が置換を予告していたのに実行されず落ちた。
   - いつ起こるか: 設計docに「置換する」と書いても、実装レーンは docs を触らないので誰も実行しない。
   - 次どうするか: doc の置換は Leader が明示的にタスク化して architect に投げる (今回そうした)。予告だけで終わらせない。

5. **Codex が使えない期間の運用**
   - 何が課題か: `codex exec` が usage limit (〜8/3) で、しかも **exit 0 を返して何もしない**ことがある。developer が気付いたのは `git status` が空だったから。
   - 次どうするか: subagent の指示に最初から「codex が usage limit なら待たずに自力実装せよ」「exit 0 でも `git status` で確認せよ」と書く。memory 更新済。
