## 課題点

- **実装したものを push しないまま次の作業に移った (07-23)**
  - **何が課題か**: 07-23 に MVP 全部を実装・ローカル main にマージしながら push しなかった。その間に天野が同じ ws 層を触り、6 日後に統合コストとして返ってきた。コンパイル不能 2 箇所 + テストで検出できない仕様衝突 1 件。
  - **いつ起こるか**: セッション終盤に「マージまで終わった」で満足し、リモート反映を完了条件に数えていないとき。
  - **次どうするか**: **ローカル main へのマージを完了と呼ばない**。push して CI が緑になるまでが 1 単位。session report の作業記録に「push した run id」を書く運用にすれば漏れが可視化される。

- **fake store だけのテストが「緑なのに本番が落ちる」を素通しした**
  - **何が課題か**: REST ハンドラのテストは全部 interface の fake 実装なので、DB の CHECK 制約と REST のバリデーションが食い違っても検出できない。今回の emoji/stamp はまさにそれで、両者が矛盾したまま両方のテストが緑だった。
  - **いつ起こるか**: DB 制約を触る migration と、それを使う API が別のブランチ/別の人で進むとき。
  - **次どうするか**: 設計docが既に指定している `//go:build integration` の Repo 実体テストを実際に立てる。最低限「migration を当てた実 Postgres に対して各 endpoint の正常系を 1 本ずつ」通す。**それまでは「Go テスト緑」を疎通の根拠にしない**と明言しておく。

- **テストを書いたのに実行経路に繋いでいなかった**
  - **何が課題か**: web の vitest 32 本が `package.json` の test script がダミーのままで、`pnpm -r test` にも CI にも乗っていなかった。存在するのに一度も走っていないテストは、無いより悪い (あると誤認する)。
  - **いつ起こるか**: scaffold 時のダミー script を、テスト追加時に書き換え忘れたとき。
  - **次どうするか**: テストファイルを追加したら**同じコミットで `pnpm -r test` を回し、そのアプリの実行行がログに出るか目視する**。「N passed」が出ないアプリは繋がっていない。

- **必須 env を増やしたのに CI の probe を直していなかった**
  - **何が課題か**: `envRequired` を足した 07-23 の実装が、env 無しで起動する CI probe と噛み合わず、push した瞬間に赤くなった。実装時に気付ける類。
  - **いつ起こるか**: 起動時 fatal を足すとき。ローカルでプロセスを起動していないと気付けない。
  - **次どうするか**: 起動時必須 env を足したら、その場で `.github/workflows/ci.yml` の probe と Coolify env の両方を更新する。**「起動を検証している場所」を env 追加のチェックリストに入れる**。
