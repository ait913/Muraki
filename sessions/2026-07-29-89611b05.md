## 課題点

- **実装したものを push しないまま次の作業に移った (07-23)**
  - **何が課題か**: 07-23 に MVP 全部を実装・ローカル main にマージしながら push しなかった。その間に天野が同じ ws 層を触り、6 日後に統合コストとして返ってきた。コンパイル不能 2 箇所 + テストで検出できない仕様衝突 1 件。
  - **いつ起こるか**: セッション終盤に「マージまで終わった」で満足し、リモート反映を完了条件に数えていないとき。
  - **次どうするか**: **ローカル main へのマージを完了と呼ばない**。push して CI が緑になるまでが 1 単位。session report の作業記録に「push した run id」を書く運用にすれば漏れが可視化される。

- **fake store だけのテストが「緑なのに本番が落ちる」を素通しした**
  - **何が課題か**: REST ハンドラのテストは全部 interface の fake 実装なので、DB の CHECK 制約と REST のバリデーションが食い違っても検出できない。今回の emoji/stamp はまさにそれで、両者が矛盾したまま両方のテストが緑だった。
  - **いつ起こるか**: DB 制約を触る migration と、それを使う API が別のブランチ/別の人で進むとき。
  - **次どうするか**: 設計docが既に指定している `//go:build integration` の Repo 実体テストを実際に立てる。最低限「migration を当てた実 Postgres に対して各 endpoint の正常系を 1 本ずつ」通す。**それまでは「Go テスト緑」を疎通の根拠にしない**と明言しておく。

- **テストを書いたのに実行経路に繋いでいなかった**
  - **何が課題か**: web の vitest 32 本が `package.json` の test script がダミーのままで、`pnpm -r test` にも CI にも乗っていなかった。存在するのに一度も走っていないテストは、無いより悪い (あると誤認する)。
  - **いつ起こるか**: scaffold 時のダミー script を、テスト追加時に書き換え忘れたとき。
  - **次どうするか**: テストファイルを追加したら**同じコミットで `pnpm -r test` を回し、そのアプリの実行行がログに出るか目視する**。「N passed」が出ないアプリは繋がっていない。

- **必須 env を増やしたのに CI の probe を直していなかった**
  - **何が課題か**: `envRequired` を足した 07-23 の実装が、env 無しで起動する CI probe と噛み合わず、push した瞬間に赤くなった。実装時に気付ける類。
  - **いつ起こるか**: 起動時 fatal を足すとき。ローカルでプロセスを起動していないと気付けない。
  - **次どうするか**: 起動時必須 env を足したら、その場で `.github/workflows/ci.yml` の probe と Coolify env の両方を更新する。**「起動を検証している場所」を env 追加のチェックリストに入れる**。

- **「実 DB に繋いでいない」を 6 日間放置していた**
  - **何が課題か**: 07-23 に MVP を実装し終えた時点で、実 DB に繋ぐのは Supabase 待ちだと思い込んでいた。実際にはローカル Postgres で今日の作業が全部できた (migration 適用・Repo 実体テスト・REST e2e・ブラウザ E2E)。**外部依存を待つ理由が実は無かった**。
  - **いつ起こるか**: 「本番と同じもの」が無いと検証できないと決めつけたとき。今回なら「Supabase が無いと DB テストできない」。実際は Postgres であればよく、Supabase 固有部分 (auth.users / anon ロール) は 30 行の shim で埋まった。
  - **次どうするか**: 外部サービス待ちで止まったら、**「その依存の何が本当に必要か」を最小に分解する**。DB なら Postgres、認証なら鍵ペア。丸ごと本物を待たない。

- **本番でしか出ない層を検証していなかった**
  - **何が課題か**: ローカルの e2e が全部緑でも、リバースプロキシ越しの挙動 (Nginx が 404 を HTML に差し替える) と env の値ミス (`/ws/ws`) は落ちなかった。今日見つけた本番バグ 2 件はどちらもローカルでは原理的に踏めない。
  - **いつ起こるか**: 自前スタック (Cloudflare → Nginx → Traefik → app) を挟んでいるのに、検証をアプリ層で止めたとき。
  - **次どうするか**: **デプロイ後に「本番の URL に対して」主要動線を 1 周叩く**のを完了条件に入れる。今日は curl で E4→E9 と WS probe を通した。この 10 分が 2 件を捕まえた。

- **ローカルと CI で別バージョンのツールが走る状態を放置していた**
  - **何が課題か**: `.npmrc` の `manage-package-manager-versions=false` が「決定論的にする」意図で入っていたが、実際には**ローカル pnpm 9.15.0 / CI・EAS pnpm 11.13.0** という乖離を固定していた。pnpm 11 が `.npmrc` を読まなくなった変更が、ローカルでは一切見えないまま設定を無効化していた。
  - **いつ起こるか**: ツールのメジャー更新で設定の置き場所が変わったとき。警告が出ない変更だと、設定ファイルを見ても異常が無い。
  - **次どうするか**: **設定が効いているかはファイルでなくコマンドで確かめる** (`pnpm dlx pnpm@<packageManager の版> config get node-linker`)。`packageManager` を固定しているなら、ローカルもそれに追従させる方が乖離が減る。

- **ログを読む前に 2 回推測でビルドを回した**
  - **何が課題か**: EAS のログが brotli で展開できず、「metro のバージョン不整合だろう」と推測して依存を上げ、外した。1 ビルド十数分 × 2 を空費した。
  - **いつ起こるか**: ログ取得に手間取ったとき。「取れないから推測で進める」に流れる。
  - **次どうするか**: **ログが読めないなら、まずログを読む手段を確保する**のを 1 手目にする。今回は Node の `zlib.brotliDecompressSync` で 1 分で読めた。読めた瞬間に原因は一発だった。

## いい点

- **「テキスト衝突しない衝突」を疑って全層 grep したこと**
  - **何が良かったか**: git のマージは 2 ファイルしか衝突を報告しなかったが、実際の破壊は改名によるコンパイルエラーと DB CHECK と REST の仕様不一致だった。後者は git も型検査も検出しない。
  - **いつ効いたか**: マージ直後に `emoji|stamp` を全ファイル種別で grep し、Go/TS/SQL/設計doc の 7 箇所を洗い出せた。
  - **どう続けるか**: **他人のブランチを取り込んだら、衝突ファイル数を信用せず「相手が変えた概念」で grep する**。今回なら「message_type」「envelope 型名」。

- **本番の確認を「200 が返った」で終わらせなかったこと**

  - **いつ効いたか**: 実際にデプロイログに `--build-arg NEXT_PUBLIC_API_BASE` が出ていること + chunk 内の文字列ヒットの 2 点で確定できた。
  - **どう続けるか**: **ビルド時埋め込みの検証は成果物 (bundle) を grep する**。env 一覧が正しいことは証拠にならない。

- **裁定を 2 問に絞って先に取ったこと**
  - **何が良かったか**: emoji/stamp と Supabase の作り方だけを AskUserQuestion で確定させ、以降は止まらずに統合〜デプロイまで走れた。
  - **いつ効いたか**: emoji/stamp は Go/TS/SQL/設計doc の 7 箇所に波及したので、後から覆ると手戻りが大きかった。
  - **どう続けるか**: **波及範囲の広い仕様分岐は、着手前にまとめて 1 回で聞く**。

- **外部依存待ちの間に、待たなくていい部分を先に潰したこと**

  - **何が良かったか**: 今日 5 回赤を見たが、内訳は「一過性ネットワーク 1・自分のテストデータが不正 1・自分のテストハーネスの構造ミス 1・自分の env ミス 1・実装バグ 1」で、実装バグは 1 件だけだった。毎回ログを読んで帰属を確かめたので、正しい実装を疑って壊す事故が無かった。
