## 課題点

- **コード内 TODO コメントは負債台帳に載らない限り履行されない** / いつ起こるか: 「〜になったら切り替えろ」型のコメントの条件が満たされた時 / 次どうするか: この型の TODO は書いた時点で .knowledge (known-failures の「仕様逸脱」分類) に登録する。08-08 の 2 日間障害の根本原因

- **同一 worktree での多レーン並走はディレクトリ専有の口頭契約に依存した** / いつ起こるか: developer×2 + reviewer を 1 worktree に同時召集した時 / 次どうするか: 今回は「編集可は apps/X のみ」の明示指示 + Leader のレーン別選択ステージで事故ゼロだったが、`git add` の誤爆余地はある。依存があるときは「先行フェーズをコミット → 子 worktree 分岐」も検討
- **バックグラウンド監視の 10 分上限と EAS ビルドの相性** / いつ起こるか: build 監視ループが 10 分を超えるとき / 次どうするか: 監視窓を数 poll に切って exit code で継ぎ足す方式が機能した。これを既定にする
- **Codex 修正パスは PATH (golangci-lint) を持たない** / いつ起こるか: sandbox 実行時 / 次どうするか: 修正後の lint/テストは Leader 側で必ず回す (今回 unused 残骸 1 件を Leader の再検証が拾った)
