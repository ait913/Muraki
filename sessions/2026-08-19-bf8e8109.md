## 課題点

- サブエージェントの無音ハングを 90 分放置した
  - **何が課題か**: 「完了通知が来ない = 走っている」と思い込み、flutter test ハングと API エラー死を検知できなかった
  - **いつ起こるか**: 長時間レーン (30 分超) をバックグラウンドで走らせている間。ネットワーク断で悪化
  - **次どうするか**: 長時間レーンには最初から活動監視 (worktree+scratchpad の mtime) を付ける。今回の Monitor パターンを流用
- Coolify env の is_buildtime 既定 true で JWT_SECRET がビルドログに漏れた
  - **何が課題か**: secrets 投入の既定値が危険側。ローテーションで実害は塞いだが検知は事後
  - **いつ起こるか**: Coolify に multiline/secret env を入れる全ケース
  - **次どうするか**: coolify-api.md に追記済み。secrets は必ず is_buildtime:false を明示
- ビルドフラグ依存の構成が本番事故を生んだ (build 5 の localhost 焼き込み)
  - **何が課題か**: dart-define 頼みの API URL は「付け忘れ = 全滅」で、subagent の手順再現性に賭けていた
  - **いつ起こるか**: ビルドを subagent に委譲するたび
  - **次どうするか**: 危険な既定値を安全側に倒す (本番 URL を既定に) + preflight.sh でバイナリ検査。「設定はコードに、検証は成果物に」を横展開
- subagent への追加指示が正規ルート外と誤解されうる
  - **何が課題か**: SendMessage の追加指示を b9 エージェントが「injected channel」として拒否。「アップロードはしない」等の言葉が別の意味に誤読された
  - **いつ起こるか**: 走行中レーンへのスコープ変更時
  - **次どうするか**: スコープ変更は新レーンで明示的な権限文と共に発注する方が確実。禁止事項の言葉は多義性を避ける (「TestFlight 配布は Leader が行う」等)
- known-failures.md が並列レーンのマージで 3 回コンフリクト
  - **何が課題か**: 全レーンが同一台帳ファイルに追記する設計
  - **いつ起こるか**: 並列 worktree 運用時のマージ
  - **次どうするか**: ベースライン行はレーン別ファイルか、マージ時 union 解決を機械化 (今回の python 解決スクリプトを scripts/ 化する価値あり)
