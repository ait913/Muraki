## 課題点

- **負のコントロールの空振り**: 何が課題か = 定数名を当てずっぽうで sed して変異が入らず「exit 0」を見て一瞬 OK と読みかけた / 次どうするか = 変異は `git diff` で実際に入ったことを確認してからテストを回す (今回はそうして 3 回目で成立)
- **ゲート修正が回帰 20 本を生んだ**: 何が課題か = シェル dispose で provider を触る修正が widget テストの teardown と衝突、サインイン条件の追加が doc 未更新のまま Reviewer テストと衝突 / 次どうするか = ゲート修正も「doc を先に置換 → Codex 実装 → 全テスト」の順にする (今回は実装先行で doc が後追いになった)

- **headless Chrome のスクショが全滅**: 何が課題か = MapLibre の見た目 (最重要の検証対象) を Leader が目視できないまま渡した / いつ起こるか = 2026-09-18 深夜、about:blank でも再現 / 次どうするか = about:blank の capture が 15s で返らなければ即 evaluate 検証に切替 (knowledge 記載)。翌日以降に再発するか確認する
- **Codex 発注プロンプトが長い (約 6,000 字)**: 何が課題か = ノブ名を Leader が推測で検証に使い、2 つハズレ (`additive`/`silver` → 実際は `linear`/`all`) / 次どうするか = 発注時に「ノブの値名を完了報告に列挙せよ」を入れる
- **設計 doc がライブラリの版を取り違えた** (platform_interface 0.27.0 の encode 退避を前提にしたが lock は 0.26.2): 何が課題か = Researcher が版を報告していたのに Architect が別版のソースを読んだ / 次どうするか = Architect は pub cache を読む時 `pubspec.lock` の版ディレクトリだけを開く (role/architect.md に追記候補)
- **Codex の「逸脱報告」を Leader が裁定せず流した** (`simplifyTrack` の maxPoints 厳守): 何が課題か = Codex は完了報告で逸脱を正直に書いていたのに、Reviewer RED になるまで doc と実装の不一致が放置された / 次どうするか = Codex 完了報告の「逸脱」欄は検収時に必ず「doc を直す / 実装を戻す」のどちらかを即決する
