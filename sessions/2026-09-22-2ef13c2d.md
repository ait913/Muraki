## 課題点

- **puppeteer の `page.type` が ASC の React textarea で timeout**
  - **何が課題か**: 1,000 字超を 1 打鍵ずつ流すと `Runtime.callFunctionOn timed out`、1 巡無駄にした
  - **いつ起こるか**: React 制御の textarea に長文を入れる時
  - **次どうするか**: 最初から native setter + input イベント (ascweb.js の eval)。knowledge に記載済み
- **Touri の「まず探索」が本線生成の途中で来た**
  - **何が課題か**: 16 タイプの波 1-3 を起動した直後に 5×5 探索へ切替、12 体分の Codex 画像生成が宙に浮いた
  - **いつ起こるか**: ビジュアル系で「方向性の裁定」を経ずに Architect の 1 案で本線を走らせた時
  - **次どうするか**: キャラ・ロゴ等は「方向性 × 質感の探索 → 裁定 → 本線」を既定順にする (テキストの設計 doc 承認だけでは見た目の裁定にならない)

- **Codex の修正が import 漏れでコンパイルを壊した**
  - **何が課題か**: `Timer` を足して `dart:async` を import せず、テスト 5 dir がロード失敗になった
  - **いつ起こるか**: Codex が flutter analyze を回せない sandbox で小修正をする時
  - **次どうするか**: Codex 修正パスの直後は必ず `flutter analyze lib` を先に回してからテストへ (今回は同時に回して 1 巡無駄にした)
- **`flutter build ipa` が capability 追加で使えなくなった**
  - **何が課題か**: entitlements 変更後、Xcode アカウント無しでは内蔵 archive が profile を更新できない
  - **いつ起こるか**: Associated Domains 等の capability を初めて足すビルド
  - **次どうするか**: CLAUDE.md を xcodebuild archive + ASC キー手順に置換済み。今後はこの手順のみ
- **発注プロンプトが doc §12 と食い違い、機械修正が宙に浮いた**
  - **何が課題か**: Leader が「置換テストは触るな」と書き、doc は「機械修正は Codex 担当」だったため Codex がどちらにも従えず未実施 → Reviewer に 37 件のコンパイル修正が回った
  - **いつ起こるか**: doc に担当分けが書いてある時に Leader が別の担当分けを書く
  - **次どうするか**: 発注プロンプトの担当分けは doc §12 を引用するだけにする
