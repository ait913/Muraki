## 課題点

- Reviewer の XCUITest が 3 時間かかった
  - **何が課題か**: Mac の load 20〜44 (Docker VM + 他セッションの Codex/build 並走) で XCUITest 1 本が 80〜230 秒、ランナー落ちも発生。偽 fail の切り分け (alert/シートの最初の 1 タップが落ちる) に大半を使った
  - **いつ起こるか**: 他レーンが同時に走っている時の XCUITest 全般
  - **次どうするか**: XCUITest を含む Reviewer は並走レーンを止めてから回す。1 タップ落ちは role/reviewer.md #41 に記録済、次回はテストの初版から再タップ付きで書く
- 負のコントロール agent が Leader の追加条件 (Codex 完了まで編集を待て) を受け取る前に編集を始めていた
  - **何が課題か**: 同一 worktree で Codex レビューと一時編集を並走させると、Codex が一時編集を読む可能性がある (今回は Codex が未コミット差分を除外したと明言し無害)
  - **いつ起こるか**: ゲートのレビューと負のコントロールを同じ worktree で同時に走らせた時
  - **次どうするか**: 条件は召集 prompt の時点で入れる (後追いの SendMessage は間に合わない)。または負のコントロールは Codex 完了後に直列で回す
- Coolify の `/deploy` が GET → POST に変わっていた
  - **何が課題か**: CLAUDE.md の手順が黙って陳腐化していた (GET は JSON でエラーを返すだけ)
  - **いつ起こるか**: 外部 API の手順を CLAUDE.md に固定している全 PJ
