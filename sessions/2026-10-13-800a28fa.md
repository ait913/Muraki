## 課題点

- 版ゲートの設計に「サインインを除外する」観点が無かった (pattern/native-client-version-gate-minimal.md にも無い)
  - **何が課題か**: Apple の「初回限定で渡る情報」を止める経路があると、復旧不能なデータ欠損になる
  - **いつ起こるか**: 全リクエストに middleware を掛ける設計をするとき
  - **次どうするか**: pattern に「初回限定情報を受ける endpoint は gate の対象外」を追記 (本セッションで実施)
- 設計doc §8-3 (既存テストの移行) の漏れが 3 件 (IB9 / LS21 / LG9 の時刻衝突)
  - **何が課題か**: 方針変更 (ip_hash 撤去、migration 追加) で陳腐化する既存テストを Architect が列挙しきれない
  - **いつ起こるか**: ログやスキーマの方針を変えるとき
  - **次どうするか**: Architect が `grep -rn '<撤去する語>' *_test.go` を §8-3 の手順に含める。Reviewer の substring assert は時刻と衝突しない値を使う
- Codex ゲートの「既存エンドポイント共通の性質」を本件固有の major として出す傾向 (relink の TOCTOU、インフラ IP)
  - **何が課題か**: そのまま受けると範囲が膨らむ
  - **いつ起こるか**: 2LLM ゲートのたび
  - **次どうするか**: Leader が「既存と同じ性質か」を 1 問だけ確認して却下/受理を即決 (本セッションでは 2 件却下、根拠を PR 本文に残した)
- PR #15 でゲートを外すとき、「そのゲートが今どのクライアントを止めているか」を確かめなかった
  - **何が課題か**: 0.2.0 を止めていたのが互換レベルのゲートだけだったので、撤去で 0.2.0 が素通りになった (項目 27)
  - **いつ起こるか**: 版ゲート・認可・限流など「止める仕組み」を緩めるとき
  - **次どうするか**: 緩める前に prod ログで「現在そのルールで弾かれているリクエスト」を集計し、0 件でなければ誰かを確認する
- Bash の `&&` 禁止フックが heredoc 内の JS / Go ソースにも効く
  - **次どうするか**: `&&` を含むスクリプトは Write ツールでファイルに書いてから実行する
- ASC App Privacy のウィザードは途中でブラウザを閉じるとデータ型の追加ごと消える。最終ボタンは 保存 でなく 公開 (既公開の App Privacy の場合)
  - **次どうするか**: knowledge の手順に追記済み (下記)
