# 2026-10-28 7342b79d — aiserver2 の BIOS 起動手順と表示先の切り分け

## 作業記録

1. Touri から「aiserver2 の UEFI BIOS に入りたいが FUJITSU ロゴが出ない、DVI/D-Sub どちらにも映らない」の相談。機体は knowledge 既存の D552/K (BIOS 4.08、UEFI)
2. 製品ガイド (B5FK5061) と BIOS セットアップメニュー一覧 (B6FHA895) を pdftotext で読み、F2 押しっぱなし起動 / 高速起動 / 起動時の自己診断画面 (既定「使用しない」= ロゴ表示) / 「モニタを PC より先に ON」の記述を確認
3. サーバーを ssh で実測: `OsIndicationsSupported` = `01` (firmware UI 起動に対応)、efibootmgr timeout 1 秒、GRUB timeout 0、dmesg に BGRT + efifb 1024x768 (firmware はロゴを描画している)、DVI-D (HDMI-A-1) に EDID 256 バイト、D-Sub (VGA-1) は EDID 0 バイト
4. Touri 指示で `systemctl reboot --firmware-setup` を実行 (2 回)。いずれも 90 秒 ssh 復帰なし = firmware で停止。1 回目は表示されず Touri が物理で電源入れ直し (09:57 再起動)
5. Touri が古いモニタを D-Sub 直結で接続 → BIOS と FUJITSU ロゴが表示。DVI-D→HDMI 変換のモニタには firmware 段で出なかった
6. knowledge `gotcha/onprem-fujitsu-d552-cmos-reset-and-beep-codes.md` の「画面が出ない」項を表示先の実測と firmware-setup 手順に置換、INDEX 再生成
7. Touri が DVI→HDMI 単独接続でも試して不可を確認 (優先順位の問題でなく firmware 段で駆動できない)。knowledge の記述をその事実に修正
8. 目的は AC 投入時の自動起動設定 (BIOS 側で Touri が設定)。10:14 に Ubuntu 復帰、コンテナ 39/40 Up (残 1 は一回限りの pass-migrate、正常)、docker/cloudflared active、coolify.aisaba.net 302 を確認してクローズ

## 課題点

- **何が課題か**: 本番サーバーに firmware-setup 再起動をかける前に、表示経路 (D-Sub の EDID 0 バイト) を根拠に「映らないかもしれない」と先に言うべきだった
- **いつ起こるか**: リモートから firmware を触る作業で、物理モニタの状態が確認できないとき
- **次どうするか**: EDID 0 バイトの端子しか無い場合は再起動前に「古いモニタ + D-Sub 直結」を用意させる

## いい点

- **何が良かったか**: Windows の Shift+再起動の実体 (OsIndications) を firmware 変数で実測し、Linux からの同等手順を根拠付きで出せた
- **いつ効いたか**: ロゴもキー入力タイミングも不要になり、2 回とも確実に firmware で停止した
- **どう続けるか**: UEFI 機の BIOS 作業は `OsIndicationsSupported` の確認を最初にやる
