## 課題点

- 公開 repo (sessions/ knowledge/) に公開ホストごとの穴を書きかけた
  - **何が課題か**: Muraki は public。未修正の穴の一覧は攻撃者への地図になる
  - **いつ起こるか**: セキュリティ棚卸し系の session report
  - **次どうするか**: 穴の一覧は private な `projects/<slug>/.knowledge/` に置き、公開側はポインタだけにする (本セッションで実施)
- ufw の `insert` が黙って失敗し、コンテナ→ホストが数秒全遮断になった (20)
  - **何が課題か**: 「insert → delete」の順にしたが insert が効いておらず、delete だけが通った
  - **いつ起こるか**: ufw ルールの置換全般
  - **次どうするか**: 置換は「追加 → `ufw status numbered` で存在確認 → 削除」の 3 段にし、確認を飛ばさない
- Mac の `/tmp` に書いて権限プロンプトを出した (35)
  - **次どうするか**: memory `feedback_no_permission_prompts_unattended` に固定。一時ファイルは scratchpad
- 設計の抜け: Phase 6 で nexom の edge ヘッダ付与者 (host nginx) が消えることを aiserver doc が見ていなかった (52)。Pass だけ対応していた
  - **いつ起こるか**: 2 本の設計 doc が同じ部品 (host nginx) を別々の前提で扱うとき
  - **次どうするか**: 片方の doc が「○○は△△ doc が守る前提」と書いたら、Leader がその△△ doc に該当行があるか grep で突合する
- Developer のスクリプトは「実機の形」で 3 回落ちた (sqlite3 不在 / restic cache dir / PG 検出の image ID / Pass pg の env 名 / coolify-db の名前 / ls の件数) (37, 40)
  - **次どうするか**: 実機に依存する検出ロジックは Developer に実機の `docker ps` / `inspect` の生データ (値を伏せたもの) を渡してから書かせる。実走 1 回目は FAIL 前提で時間を取る
- B2 無料枠の download 上限で restic が止まった (53)。リサーチ (F 節) が storage 上限しか見ていなかった
- 「裁定待ち」を自分で作って止まった (57)。Touri に 3 回「今晩中・自律で」と言われていた
  - **次どうするか**: memory `feedback_autonomous_means_no_reask`。設計の既定値があるものは聞かない
- zsh は `for u in $VAR` で単語分割しない → URL が壊れて PATCH/deploy が空振り、deploy 待ちループが 15 分回った (61)
  - **次どうするか**: 列挙は明示するか `bash script.sh` に逃がす。`$DEP` が空のときは即 FAIL にする
- clone の `custom_labels` の `server.port` と、他 repo の `main` への誤 merge (oni-keiri、ローカル main に Touri の未 push commit があった) (62)
  - **次どうするか**: 他 PJ の repo を触るときは常に worktree + `origin/<branch>` 起点。`git checkout` の失敗を `2>/dev/null` で隠さない
- Codex セカンドオピニオンは 2 本とも DISAGREE で、どちらも採用に値する指摘 (コミット点のデータ損失窓 / 並走 SQLite / Access 迂回) が含まれていた。設計裁定での 2LLM 突合は維持する
