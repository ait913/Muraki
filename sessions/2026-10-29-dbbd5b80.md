## 課題点

- Codex ゲートが設計の穴 (tx の外の後処理) を拾い、Claude 側 5 レビューは全て見逃した
  - **何が課題か**: Reviewer は「設計 doc からテスト生成」なので、設計自体が手順 8 を tx 外に置いていると、その穴はテストにならない。Architect も「既存流儀どおり」で疑わなかった
  - **いつ起こるか**: 「tx で原子化」を謳う設計で、tx の後に失敗しうる副作用 (生成・外部呼び出し) が残るとき
  - **次どうするか**: Architect ノートに「原子性を謳う節は、tx の後段に失敗しうる処理が残っていないかを明記する」を足す (今回 Architect が §11 に不採用案として記録済)。リリース前ゲートの Codex 突合は今回も有効だった = 継続
- 設計 doc の確認手順に存在しない endpoint (`GET /api/version`) が書かれていた
  - **何が課題か**: Researcher/Architect が route の prefix を実測せず書いた。デプロイ後の確認で 404 を踏んだ
  - **いつ起こるか**: §9 のような「確認コマンド」を doc に書くとき
  - **次どうするか**: 確認コマンドは既存テストの request path から写す (reviewer が `/version` で書き直している)
- Coolify の app UUID が CLAUDE.md と食い違っていた (aiserver 堅牢化の clone で変更、記載更新漏れ)
  - **何が課題か**: 他セッション (aiserver) が app を作り直したとき、各 PJ の CLAUDE.md を追随させていなかった
  - **いつ起こるか**: インフラ側のセッションがリソースを clone/再作成したとき
  - **次どうするか**: デプロイ前に `GET /applications` で名前から UUID を引く (今回それで復旧)。aiserver 側の handoff に「PJ の CLAUDE.md の UUID を置換」を含める
- TestFlight が Apple PLA 承諾待ちで止まった (無人実行の盲点)
  - **何が課題か**: 認可の壁は Touri しか越えられない。archive 後に判明するので時間を食う
  - **いつ起こるか**: Apple の規約改定後の初回配布
  - **次どうするか**: `gotcha/apple-pla-update-blocks-cloud-signing`。archive 前に export を dry-run する手は無いので、着手時に ASC のバナーを人が見る運用
